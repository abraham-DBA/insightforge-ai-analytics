## 🧠 Overview

InsightForge AI Analytics is a full-stack SaaS platform that enables businesses to create and deploy AI-powered chatbots trained on their own knowledge base. Users can upload content, organize it into topical **Sections**, customize the chatbot's appearance, and embed it as a widget on any website.

Authentication is handled via **Scalekit** (SSO/OAuth 2.0), conversations are stored in a serverless **NeonDB** PostgreSQL database, and AI responses are generated by **Google Gemini**.

## 🚀 Getting Started

### Prerequisites

- **Node.js** ≥ 18
- **npm**, **yarn**, **pnpm**, or **bun**
- A **NeonDB** serverless PostgreSQL database
- A **Scalekit** account for SSO authentication
- A **Google AI** API key for Gemini

### Installation

```bash
# Clone the repository
git clone https://github.com/your-org/insightforge-ai-analytics.git
cd insightforge-ai-analytics

# Install dependencies
npm install
```

### Run in Development

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## 🔑 Environment Variables

Create a `.env` file in the project root with the following variables:

```env
# Database
DATABASE_URL=postgresql://user:password@host/dbname?sslmode=require

# Scalekit Authentication
SCALEKIT_ENV_URL=https://your-env.scalekit.cloud
SCALEKIT_CLIENT_ID=your_client_id
SCALEKIT_CLIENT_SECRET=your_client_secret
SCALEKIT_REDIRECT_URL=https://yourdomain.com/api/auth/callback

# Google Gemini AI
GOOGLE_AI_API_KEY=your_google_ai_api_key

# Widget JWT Security
JWT_SECRET=your_secure_random_jwt_secret_min_32_chars

# App
NODE_ENV=production
NEXT_PUBLIC_APP_URL=https://yourdomain.com
```

> [!IMPORTANT]
> Never commit your `.env` file to version control. The `.gitignore` is pre-configured to exclude it.

## 🗄 Database Setup

InsightForge uses **Drizzle ORM** with **NeonDB** (serverless PostgreSQL). The schema includes tables for users, sessions, metadata, knowledge sources, sections, conversations, messages, and widgets.

```bash
# Generate migration files from schema
npm run db:generate

# Apply migrations to the database
npm run db:migrate

# Or push schema directly (useful for development)
npm run db:push
```

### Schema Overview

| Table | Purpose |
|---|---|
| `user` | Authenticated users linked to an organization |
| `session` | Opaque server-side session tokens |
| `metadata` | Business profile (name, website URL, external links) |
| `knowledge_source` | Content sources (URLs, raw text) used to train the chatbot |
| `sections` | Topic-focused groups of knowledge sources with tone & scope |
| `chatBotMetaData` | Chatbot appearance, welcome message, and allowed domains |
| `team_members` | Organization collaborators with roles and invite status |
| `conversations` | Chat sessions initiated via the embedded widget |
| `messages` | Individual messages within a conversation |
| `widgets` | Deployed widget configurations with domain restrictions |

## 🔌 API Reference

All API routes live under `/app/api/` and are implemented as Next.js Route Handlers.

### Authentication
| Method | Route | Description |
|---|---|---|
| `GET` | `/api/auth` | Initiate OAuth 2.0 login flow with Scalekit |
| `GET` | `/api/auth/callback` | Handle OAuth callback, create session |

### Chat
| Method | Route | Description |
|---|---|---|
| `POST` | `/api/chat/test` | Test chatbot in the playground (authenticated) |
| `POST` | `/api/chat/widget` | Handle widget chat messages (JWT-authenticated) |

### Knowledge & Sections
| Method | Route | Description |
|---|---|---|
| `GET/POST` | `/api/knowledge/*` | Fetch, create, or delete knowledge sources |
| `GET/POST` | `/api/section/*` | Fetch, create, or delete chatbot sections |

### Widget & Embedding
| Method | Route | Description |
|---|---|---|
| `POST` | `/api/widget/session` | Issue a JWT session token for an embedded widget |

### Team & Organization
| Method | Route | Description |
|---|---|---|
| `GET/POST` | `/api/team/*` | Manage team member invites and roles |
| `POST` | `/api/webhook` | Scalekit webhook for organization events |

## 🌐 Embeddable Widget

Once your chatbot is configured, you can embed it on any website using the generated script snippet from the **Chatbot Playground → Embed Code** tab.

```html
<script
  src="https://yourdomain.com/embed/widget.js"
  data-widget-id="YOUR_CHATBOT_ID"
  async
></script>
```

### How It Works

1. The script loads and calls `/api/widget/session` with the `widget_id`
2. The server validates the requesting domain against the **allowed domains** whitelist
3. If authorized, a signed **JWT** (2-hour expiry) is returned
4. The widget uses this token to authenticate all subsequent chat requests
5. Blocked domains receive a `403 Unauthorized domain` response

### Domain Whitelisting

Configure allowed domains in **Dashboard → Chatbot → Appearance Settings**. Leave empty to allow all origins (useful for development).

## 🔐 Security

InsightForge implements production-grade security practices. See [SECURITY.md](./SECURITY.md) for full implementation details.

**Highlights:**

- ✅ **Opaque session tokens** — cryptographically random 64-char hex tokens stored server-side; no sensitive data in cookies
- ✅ **CSRF protection** — OAuth state parameter validated on every login callback
- ✅ **httpOnly cookies** — session tokens inaccessible to JavaScript (XSS mitigation)
- ✅ **Secure + SameSite=Lax** — HTTPS-only in production, CSRF-safe cross-origin behavior
- ✅ **JWT widget sessions** — short-lived (2h) signed tokens for widget authentication
- ✅ **Domain whitelisting** — unauthorized domains blocked at the session issuance layer
- ✅ **Cascade deletion** — sessions automatically cleaned up when users are removed

### Reporting Vulnerabilities

Please email **security@insightforge.com** with vulnerability details. Do not disclose publicly before a fix is released. See [SECURITY.md](./SECURITY.md) for our full response timeline.

## ☁️ Deployment

### Vercel (Recommended)

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new)

1. Push your repository to GitHub
2. Import the project into [Vercel](https://vercel.com/new)

```bash
npm run build

# Start the production server
npm run start
```
